# TruongCleaner: Rule catalog v1

This is the source of truth for what the app scans and cleans. Builders turn
each row into a `Rule` value in `Packages/CleanerKit/Sources/CleanerCore/Catalog/`.
A rule that is not in this file does not ship. Changes go through the
orchestrator.

Written 2026-11-06 from facts in `docs/RESEARCH.md` and `docs/research/`. Our
own wording and structure; no code or rule files were copied from any tool.

---

## 1. Tiers

| Tier | Selected by default | User can clean | Meaning |
|---|---|---|---|
| **Safe** | Yes | Yes | Regenerated by its owner; losing it costs time, not data. |
| **Review** | No | Yes, after seeing the list | Probably safe, but may hold the user's only copy or be costly to rebuild. |
| **Info** | n/a | No (we show the fix) | Real space use that only macOS, root, or the owning app can reduce. We show size, what it is, and the sanctioned action. |
| **Protected** | n/a | Never | Always excluded, even if a rule's root contains it. |

## 2. Rule fields

| Field | Meaning |
|---|---|
| `id` | Stable ID, e.g. `user.caches`. Used in history and settings. |
| `category` | Sidebar group: `caches`, `logs`, `trash`, `browsers`, `apps`, `developer`, `mail`, `ios`, `installers`, `system`. |
| `tier` | Safe, Review, Info. |
| `roots` | Absolute folders (with `~`) the rule may look in. Nothing outside them. |
| `match` | What inside a root counts: `children` (each direct child), `glob` (pattern under the root), `files(ext)`, or `ownerCommand`. |
| `depth` | How deep to look under the root for matches. Sizing always goes all the way down. |
| `minAge` | Only items whose newest modification inside is older than this. |
| `keepNewest` | Keep the N newest matches (per group). |
| `owner` | Bundle IDs or process names that must **not** be running. Unknown = keep. |
| `access` | `user`, `fda` (needs Full Disk Access), `root` (Info only in v1). |
| `excludes` | Rule-local exclusions on top of the global protected list. |
| `action` | `trash` (default), `ownerCommand(argv)`, or `none` (Info). |
| `explain` | One plain sentence shown in the UI: what it is and what happens if removed. |

## 5. Test obligations per rule

Every rule ships with Swift Testing cases on fixture trees that prove:

1. It finds what it should, and only inside its roots.
2. Its age, keep-newest and owner guards hold (a fresh file, a newest item and a "running" owner are all kept).
3. Global protected paths inside its root are never offered.
4. Symlinks out of the root are not followed.
5. Info rules never produce a delete action.
