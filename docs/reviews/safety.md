## Checked and found correct

- **One door:** every app call site that deletes goes through `Cleaner` → `SafetyGate`. The call sites are Smart Clean, Developer files and projects, Uninstall, and Empty Trash (`trash.user`, permanent + `permanentConfirmed`). Put Back and Free Space Now go through `UndoService`. The only direct deletes are in `Update/` (rule 16a, plus findings 12–13).
- **Path resolution:** the gate resolves the real path of the parent only, never of the item. It denies `.`/`..` names. It checks roots by real path *and* by the path as scanned. It applies the protected list and user exclusions to the real path, with `/System/Volumes/Data` folded, NFC and lowercase. User exclusions also block ancestors of an excluded folder.
- **Symlinks:** the gate finds a symlinked ancestor between the root and the item. `lstat`/`getattrlist(FSOPT_NOFOLLOW)`/`O_NOFOLLOW` are used throughout. The Matcher refuses symlink items for non-`children` rules. `trashItem` and `removeItem` act on a link, not on its target.
- **Bundles:** the gate refuses an item that is inside a real bundle (a folder with a bundle extension that holds a marker). It allows a whole `.app` only for `installers.macOS` and `apps.uninstall`, decided by rule ID.
- **SIP and flags:** `SF_RESTRICTED`, `SF_NOUNLINK`, immutable and append-only flags are checked on the item, and on the parent when the item is a folder.
- **Unknown means keep:** owner `.unknown`, an empty `runningApplications` list, an unresolvable owner, an age walk that is partial or has errors, a failed open-files snapshot, and a failed history write all deny. No liveness result is cached across runs.
- **Permanent clean:** `Cleaner.decide` refuses `.permanent` without `permanentConfirmed`, and refuses `deletePermanently` rules in Trash mode. Smart Clean, Developer and Empty Trash all show two dialogs before deleting. Uninstall is always Trash.
- **History order:** `begin` (with the planned list) is written before the first item. Each item's outcome is written before the next item is handled. If a write fails, the remaining items are skipped. `trashItem` never falls back to delete.
- **Put Back and Free Space Now:** both act only on `.moved` items from history whose trash URL's real parent is `~/.Trash` or `/.Trashes/<uid>` and whose fileID is unchanged. Put Back refuses an existing destination, and `moveItem` cannot overwrite one.
- **Uninstaller matching:** whole names only, compared case-insensitively. Suffix matches need at least 3 dot parts. Apple apps are refused, whether signed with `anchor apple` or with a `com.apple.` ID that is not a user applet. Running apps are refused, and an unknown running state also refuses. The app must be owned by the user and inside an Applications folder (depth ≤ 2). Name-only matches are dropped when the inventory is incomplete or when another app shares the name or last bundle-ID component. Longer bundle IDs of other apps are excluded. A launch agent needs both label and program evidence. `.app` children are never leftovers. `/Library` items are Info only. Dot-folders, Documents, Mobile Documents and CloudStorage are never searched.
- **Owner commands:** fixed argv with absolute executables. The executable must be a regular file, not world-writable, and executable. The environment is scrubbed (`PATH`, `HOME`, `LANG` plus brew/docker flags). There is a timeout and no shell. Simulator UDIDs and runtime IDs are validated against the live `simctl` list, and the device must be Shutdown. Unknown command IDs are refused.
- **Updater transport and swap:** HTTPS only, `github.com/iant4093/TruongCleaner/releases/download/` only, with redirects limited to the two GitHub asset hosts. Size limits and a time limit apply. The checksum must appear exactly once in the list. The new bundle must have the same bundle ID, a higher `CFBundleVersion`, the right minimum OS and arm64, and pass a strict, nested, all-architecture signature validation. The archive must hold exactly one `TruongCleaner.app`. Install is allowed only from `/Applications` or `~/Applications`. Old bundles are trashed only when the name is UUID-shaped, the folder is owned by the user, and the bundle ID matches.
- **Catalog vs RULE_CATALOG §4:** I compared every rule's ID, tier, roots, match and action. Info rules have `.none`/measure-only. Apart from findings 1, 4, 6, 7 and 14, the remaining differences are all narrower than the catalog: file extensions for logs, and `*/*.xcarchive`.
