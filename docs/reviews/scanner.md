## What I checked and found correct

- **`getattrlistbulk` parser (DirectoryWalker.swift).**
  - The attribute order is right: length, returned set, `ERROR` first, then `NAME`, `FSID`, `OBJTYPE`, `MODTIME`, `FLAGS`, `FILEID`, then the file group (`LINKCOUNT`, `ALLOCSIZE`), then `CMNEXT_PRIVATESIZE`. Each optional field is read only when its returned bit is set.
  - Every read goes through the bounds-checked `EntryReader` with `loadUnaligned`, so there are no alignment faults.
  - An entry needs `length >= 24` and `entryStart + length <= bufferSize`. A name needs `nameStart >= 0`, `nameStart + len <= entryLength` and `strnlen` capped by the length. A negative `attr_dataoffset` is rejected.
  - A probe confirmed that `ATTR_CMN_ERROR` is **not** set in the returned bits on success, so ordinary entries are not sent to `parseFailedEntry`. A probe of real entries matched the expected 92 bytes plus the name.
  - The name offsets kept in `frame.names` are integer offsets, not pointers, so the array can reallocate safely.
- **Descriptors.**
  - Each frame's fd is closed when its last child is taken, or in `finish`.
  - The stop path closes every frame on the stack.
  - `pushIfBelow` refuses jobs after a stop, and `assemble` drains and closes queued jobs on the last thread, after all workers have ended.
  - Every error path closes `childFD`. No leaks found.
  - `FileLimit` raises the soft limit to at most 10,240.
- **Concurrency.**
  - `JobQueue` (`@unchecked Sendable`) touches its state only under the `NSCondition`.
  - `pending` counts queued plus in-flight jobs, so idle workers end when the walk ends, and `stop()` broadcasts.
  - `WalkGroup`, `WorkerBudget`, `SizeAccumulator`, `HardLinkSet`, `DeniedList`, `ProgressReporter` and `ProgressAggregator` all use proper locks or atomics, with no lock held while calling out except the progress gate. I found no lock-order inversion.
  - The walk waits on a continuation, not on a blocked cooperative thread.
  - Extra threads go back to the budget before `onFinished` runs, so `ScanRun` cannot deadlock on `tryStartLane`.
  - The context→extras→group cycle is broken in `onFinished`.
- **Cancellation.**
  - The walker checks for stop every directory, every batch and every 64 entries.
  - `withTaskCancellationHandler` sets the stop flag.
  - `ScanEngine` cancels the detached task from `onTermination`, always yields `.finished`, and finishes the stream.
  - No `.progress` event can arrive after `.finished`, because all walker threads have ended before the walk's continuation resumes.
  - The cancellation tests pass.
- **Hard links.** A file is counted once per `(fsid, fileID)` within a walk, and only entries with a link count above 1 touch the set. Probe: a hard-linked file reports `private=0`, so freed-space estimates err low, not high.
- **Needs access.** `EPERM`/`EACCES` at the root, at `openat`, at `getattrlistbulk` and on per-entry errors is recorded as denied, never as zero. A denied folder still gets its node. `Taint` removes dates from age-guarded candidates above a denied folder. When more folders are denied than the 500 listed, every date is treated as untrusted.
- **Integer and date handling.**
  - Byte sums are `Int64` and inputs are clamped with `max(0, …)`.
  - `packTime` bounds seconds to ±9e9, so the multiplication cannot overflow.
  - `nanoseconds(of:)` and the deadline arithmetic saturate instead of overflowing.
  - `SwapProbe` uses `Int64(clamping:)`.
  - Snapshot stamps are parsed with the `en_US_POSIX` locale in the local time zone. The simctl ISO-8601 parser falls back to a format with fractional seconds.
- **Parsers against real output on this Mac.**
  - `tmutil listlocalsnapshots /` and `listlocalsnapshotdates /` print a header even with zero snapshots, so the result is an empty list, not an error.
  - The `diskutil apfs list -plist` keys `ContainerReference`, `CapacityInUse` and `Roles`, and the `diskutil info` key `APFSContainerReference`, are present.
  - The `simctl runtime list --json` fields `identifier`, `sizeBytes` (int), `deletable`, `lastUsedAt` and `runtimeIdentifier` match the parser's types.
  - The `simctl list devices --json` shape matches, and the devices test passes.
- **Process runner.**
  - Commands run with an absolute path and an exact argv allow-list, with no shell, stdin from `/dev/null`, and separate pipes drained by readability handlers, so a full pipe cannot deadlock.
  - The run has a timeout, then SIGTERM, then SIGKILL, and a drain grace period so a grandchild holding the pipe cannot keep it open.
  - It finishes exactly once, resumes the continuation once, and breaks its reference cycles.
  - Foundation reaps the child, so no zombies are left.
- **Other.**
  - `RootResolver` resolves symlinks only in the trusted base, uses `lstat` for each component, and lists with `O_NOFOLLOW`.
  - `AccessProbe` makes read-only calls only.
  - `EntryStat` checks the reply length.
  - `TopFiles` has the right heap invariants, checks `wouldAccept` before building a URL, and has a bounded capacity.
  - The `LargeFileFinder` candidate cap is 4 × limit, at most 100k.
  - In `CategoryPlan`, no carve-out path contains another.
  - The `CleanerCore/Models` value types are plain `Sendable` data with no logic hazards. Rule equality by ID is intentional.
