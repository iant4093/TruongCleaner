## Goal

One page for everything developers fill their disks with: Xcode, simulators,
package-manager caches, Docker, and build folders inside projects.

## Requirements

REQ-RULE-02, REQ-CLEAN-01 … -07, REQ-UI-02, -05, -06.

## Sections (grouped `Form`)

1. **Xcode**: the file rules `dev.xcodeDerivedData`, `dev.xcodeDeviceSupport`,
   `dev.xcodePreviews`, `dev.xcodeCaches`, `dev.xcodeDocCache`, `dev.xcodeArchives`
   (Review), `dev.xctestDevices` — same row style and selection as Smart Clean.
2. **Simulators**: a `Table` of devices (name, runtime, state, last used, size of
   `~/Library/Developer/CoreSimulator/Devices/<UDID>` measured with `BulkWalker`
   totalsDepth 0) and a `Table` of runtimes (name, version, size, last used).
   Actions: "Delete Unavailable Simulators" (`simctl.deleteUnavailable`), per-row
   "Delete…" (`deleteSimulator(udid:)` / `deleteSimulatorRuntime(identifier:)`),
   each behind a confirmation naming the item and size; disabled with the reason
   when a simulator is booted.
3. **Package managers**: file rules (`dev.swiftpm`, `dev.npm`, `dev.yarn`,
   `dev.bun`, `dev.pip`, `dev.uv`, `dev.cargo`, `dev.cocoapods`, `dev.gradle`
   (Review), `dev.maven` (Review), `dev.androidCaches`) plus owner-command rows
   (`dev.homebrew`, `dev.pnpm`, `dev.go`, `dev.goModules`): each command row shows
   "Run" (confirmation with the exact command text), then the result (exit code,
   output tail in a disclosure). Command rows whose tool is not installed show
   "Not installed".
4. **Docker**: `dev.dockerDangling` as a command row; `dev.dockerImage` as an Info
   row with its size and "Open Docker Desktop" (`NSWorkspace` open by bundle ID
   `com.docker.docker` if installed).
5. **Project folders**: a list of folders the user adds (`NSOpenPanel`, stored in
   `SettingsStore` as `projectFolders`, passed as `Environment.projectFolders`),
   a "Find Build Folders" button that scans `dev.projectArtifacts`, results
   grouped by project with Review checkboxes.

Owner-command results are recorded in history: add the result as a history
entry through `HistoryStore` if it has an API for it; if not, keep them in the
page model and list the gap in your report (do not edit CleanerKit).

Add only the needed `case` line in `RootView` and property in `AppModel`.
