# Brief 3.6: Trash and History pages

You are builder-sonnet. Implement exactly this brief. Read `AGENTS.md`, every
file in `.kiro/steering/`, `docs/UI.md` §4.7, and the merged
`Sources/CleanerActions/Clean/` and `History/` APIs (`HistoryStore`,
`UndoService`, `CleanReport`, `ItemReport`) first.

## Goal

Users can see what TruongCleaner did, put items back, and free the space of
items it moved to the Trash.

## Requirements

REQ-CLEAN-03, -04, -05, REQ-UI-02, -05, -06.

## What to build

- `src/TruongCleaner/App/Services.swift` (if not already present): one shared
  `HistoryStore` for the app at
  `~/Library/Application Support/TruongCleaner/history.jsonl`, exposed on
  `AppModel` as `services.history`. If the Smart Clean page (task 3.5) already
  created its own store, do not touch its files; create `Services.swift` and
  note in the report that 3.5 should switch to it.
- **History page** (`Pages/History/`): a `List` of cleans, newest first: date,
  mode (Trash/Permanent), totals (moved/deleted/skipped/failed), estimated and
  measured size. Selecting one shows its items in a `Table`: name, original
  location, size, outcome (with `DenyReason.userMessage` for skipped), and a
  "Put Back" button for moved items still in the Trash (disabled with a reason
  otherwise). Batch "Put Back All" for a clean. Errors show inline.
- **Trash page** (`Pages/Trash/`): header with Trash size and item count (use the
  existing `user.trash`/`trash.*` rules through `ScanEngine` with a
  `.measureOnly`-style request for `~/.Trash`; if access is denied, show the
  Needs Full Disk Access row), "TruongCleaner items in the Trash" with their total
  from history, buttons "Free Space Now" (empties only our items, via
  `UndoService.freeSpaceNow`; confirmation dialog naming the size) and
  "Empty Trash…" (permanent delete of all Trash children through `Cleaner` with
  the `trash.user` rule, `mode: .permanent`, two confirmations; never call
  deletion APIs directly).
- Both pages refresh when they appear and after any action.

Add only the needed `case` lines in `RootView` and properties in `AppModel`.
