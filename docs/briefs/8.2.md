## Goal

Ian wants to install updates from Settings. When a newer build exists, Settings >
General and the Overview banner offer **Install Update**; the app downloads it,
verifies it, swaps itself, and relaunches. No Sparkle, no shell, no third-party code.

## Design

Kit (`Packages/CleanerKit/Sources/CleanerActions/Update/` — it changes the disk,
so it lives in CleanerActions):

1. `UpdateDownloader`: downloads `TruongCleaner.zip` and `SHA256SUMS` from the
   release's `browser_download_url`s (only `https://github.com/iant4093/TruongCleaner/releases/download/…`
   or `objects.githubusercontent.com` redirects; anything else refused) into a
   fresh folder under `FileManager.default.temporaryDirectory/TruongCleanerUpdate-<uuid>`,
   with progress, cancel and a 5-minute limit. Verifies the ZIP's SHA-256
   (CryptoKit `SHA256`) against its line in `SHA256SUMS`; mismatch → stop.
2. `UpdateUnpacker`: unzips with `/usr/bin/ditto -x -k <zip> <dir>` (fixed argv,
   scrubbed env, timeout; runner rules as `OwnerProcess`). Exactly one top-level
   `TruongCleaner.app` expected.
3. `UpdateVerifier`: the new bundle's `CFBundleIdentifier` == ours,
   `CFBundleVersion` > ours, `LSMinimumSystemVersion` ≤ running OS, executable is
   arm64 (`Bundle.executableArchitectures`), and `SecStaticCodeCheckValidity` with
   `kSecCSStrictValidate` passes (ad-hoc signature is fine; it must be intact).
   Removes `com.apple.quarantine` from the new bundle if present (`removexattr`
   recursively, no `xattr` process).
4. `UpdateInstaller.swap(running: URL, new: URL) throws -> URL`: in the running
   app's parent folder, rename the running bundle to
   `.TruongCleaner-old-<uuid>.app` (renaming a running app is allowed), move the
   new one to the original path, and on any failure rename the old one back.
   Refuse if the parent folder is not writable or is not `/Applications` /
   `~/Applications` (then the UI shows the `curl … | sh` command instead).
   Returns the old bundle's new URL.
5. `UpdateCleanup.removeLeftovers(in: URL)`: on next launch, moves any
   `.TruongCleaner-old-*.app` next to the running app to the Trash (only bundles
   whose bundle ID is ours) and deletes stale `TruongCleanerUpdate-*` temp folders.
   These are the only new deletion sites; they live in `CleanerActions`.

App:

- `UpdateChecker` gains `install()` with states `idle / downloading(progress) /
  verifying / ready / installing / failed(message)`. After a successful swap it
  opens the new bundle with `NSWorkspace.shared.openApplication(at:configuration:)`
  (`createsNewApplicationInstance = true`) and then `NSApp.terminate(nil)`.
  Approve these two AppKit calls in your report (the orchestrator updates `tech.md`).
- Settings > General > Updates: "Version x (build y)", latest available build,
  **Install Update** button (disabled with a reason when not possible), progress,
  release notes link, and "Install with Terminal instead" (copies the curl command).
- Overview banner: "Install Update" button next to the existing ones.
- Call `UpdateCleanup` once at launch, off the main actor.
- Note in the UI that macOS may ask for Full Disk Access again after an update.

## Tests (`Tests/CleanerActionsTests/Update/`)

No network in tests: inject a fake downloader that serves fixture files. Cases:
checksum mismatch refused; wrong bundle ID, older build, wrong arch, broken
signature (modify a byte in a fixture ad-hoc-signed bundle you build with
`codesign -s -` in the test) refused; swap success; swap failure rolls back
(make the destination unwritable mid-way via an injected file manager);
cleanup removes only our old bundles; URL host allow-list.
