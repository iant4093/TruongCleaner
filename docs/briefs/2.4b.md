# Brief 2.4b: Overlapping rules and pruned project walks (ScanEngine)

## Problems (from the 4.2 review)

1. **Nested overlaps.** `user.caches` offers `~/Library/Caches/com.apple.dt.Xcode`
   as one item, while `dev.xcodeCaches` offers its children. The same happens
   with `com.spotify.client` (`apps.spotifyMedia`), Yarn, CocoaPods, pip,
   `org.swift.swiftpm`, Homebrew and others. The engine's duplicate check only
   compares equal paths, so sizes are counted twice and the same bytes appear in
   two rules.
2. **Project walks keep a node per entry.** `dev.projectArtifacts` walks
   user-chosen project folders with `totalsDepth` 6, so everything inside
   `node_modules` becomes a kept node. That breaks REQ-SCAN-07 and the memory budget.

## Work

1. In the engine, before matching, compute the set of expanded roots of every
   rule in the request. A candidate of rule A that **contains or equals** an
   expanded root of a different rule B is skipped with a new
   `SkipReason.coveredByOtherRule` (count it). The more specific rule keeps its
   findings. Add the case to `CleanerCore.SkipReason` (allowed). The check is by
   path components after the same real-path handling the engine already uses.
2. Add a walk option `pruneNames: Set<String>` to `WalkOptions` (allowed edit in
   `Walk/`): a directory whose name is in the set is totaled as one node (its
   subtree is still walked for size, but no nodes are kept below it). The engine
   sets `pruneNames` for `.glob` rules to the glob's final component names
   (`node_modules`, `target`, `.build`, …) so artifacts are single nodes.
   Peak memory for a fixture project with 50,000 files inside `node_modules`
   must stay under 40 MB (measure with `tcbench`).
3. Keep every existing test green; add tests: nested overlap skipped for the
   broader rule (fixture with `Caches/com.apple.dt.Xcode/x` and both rules);
   unrelated sibling still offered; prune keeps one node per artifact; totals
   unchanged with and without prune.
