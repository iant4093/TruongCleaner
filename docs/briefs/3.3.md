## Goal

The part that actually moves files: `Cleaner.preview` and `Cleaner.run` take a
plan of findings, ask `SafetyGate` about each one, move allowed items to the
Trash (or delete them only when asked), and record everything in a history file
that supports Put Back and "Free Space Now".

## Requirements

REQ-CLEAN-01, -02 (kit part: permanent needs an explicit flag), -03, -04, -05,
-06 (measure free space before/after), REQ-SAFE-01, -11.

## API (`Sources/CleanerActions/Clean/` and `History/`)

```swift
public enum DeleteMode: String, Sendable, Codable { case trash, permanent }

public struct PlannedItem: Sendable { public let finding: Finding; public let rule: Rule; public let expandedRoots: [URL] }
public struct CleanPlan: Sendable {
    public var items: [PlannedItem]
    public var mode: DeleteMode
    public var permanentConfirmed: Bool      // must be true when mode == .permanent, else the whole run is refused
}

public enum ItemOutcome: Sendable, Codable {
    case moved(to: URL), deleted, skipped(DenyReason), failed(String)
}
public struct ItemReport: Sendable, Codable { findingID, ruleID, originalPath, fsid, fileID, estimatedBytes, privateBytes, outcome }
public struct CleanReport: Sendable, Codable {
    public let id: UUID; public let startedAt, finishedAt: Date; public let mode: DeleteMode
    public let items: [ItemReport]
    public let availableBefore, availableAfter: Int64?      // volumeAvailableCapacityForImportantUsage
    public var measuredFreedBytes: Int64? { … }             // after - before (may be negative or small: Trash still holds items)
}

public struct CleanProgress: Sendable { public let done: Int; public let total: Int; public let current: URL? }

public struct Cleaner: Sendable {
    public init(gate: SafetyGate, executor: any ItemExecutor, history: HistoryStore, context: @Sendable (PlannedItem) -> GateContext)
    public func preview(_ plan: CleanPlan) async -> [UUID: Verdict]            // same gate, no executor call
    public func run(_ plan: CleanPlan, progress: @Sendable (CleanProgress) -> Void) async -> CleanReport
}

public protocol ItemExecutor: Sendable {
    func moveToTrash(_ url: URL) async throws -> URL           // returns the resulting URL in the Trash
    func deletePermanently(_ url: URL) async throws
}
public struct FileManagerExecutor: ItemExecutor { … }           // the ONLY production executor

public actor HistoryStore {
    public init(fileURL: URL)        // app passes ~/Library/Application Support/TruongCleaner/history.jsonl; tests pass a fixture file
    public func begin(_ plan: CleanPlan, id: UUID) throws
    public func record(_ item: ItemReport, cleanID: UUID) throws
    public func finish(_ report: CleanReport) throws
    public func cleans() throws -> [CleanSummary]               // newest first
    public func items(of cleanID: UUID) throws -> [ItemReport]
}

public struct UndoService: Sendable {
    /// Moves an item back from the Trash to its original path if it is still in the Trash with the same fileID
    /// and the original path is free. Records an `undone` entry.
    public func putBack(_ item: ItemReport, cleanID: UUID, history: HistoryStore) async -> PutBackResult
    /// Permanently deletes items this app moved to the Trash (from history) that still match their fileID.
    /// Never touches anything else in the Trash.
    public func freeSpaceNow(history: HistoryStore, executor: any ItemExecutor) async -> FreeSpaceReport
}
```

## Behavior

- **Choose the trash API from S3's evidence** in `docs/EVIDENCE.md` (if S3 is
  not recorded yet when you start, use `FileManager.trashItem(at:resultingItemURL:)`,
  which is callable off the main thread, and say so). Never `NSWorkspace` in the kit.
- `run`: write `begin` before the first item; for each item in order: call the
  gate; on `.allow` call the executor; write one `record` per item **before
  moving on**; then `finish`. If writing history fails, stop the run (remaining
  items `skipped(.probeFailed("history unavailable"))`) — never delete without a record.
- Items are processed serially (deletions are I/O-bound and order matters for
  nested items: if a parent was moved, its children are `missing`).
- `permanent` with `permanentConfirmed == false` → every item `skipped(.probeFailed("permanent delete not confirmed"))`, executor never called.
- Measure `availableBefore`/`availableAfter` with `URLResourceValues`
  (`volumeAvailableCapacityForImportantUsageKey`) on the home volume.
- History file: JSON Lines, one object per line with a `type` field (`begin`,
  `item`, `finish`, `undone`, `freed`); append with `FileHandle` +
  `synchronize()` per line; create the folder with `0700`; tolerate a truncated
  last line on read (skip it).
- `putBack`: gate-like checks for the reverse move: the Trash URL is inside a
  Trash (`~/.Trash` or `<vol>/.Trashes/<uid>`), `lstat` matches the recorded
  fileID, original parent exists, original path free. Uses `FileManager.moveItem`.
  This move lives in `CleanerActions` (allowed).
- `freeSpaceNow`: only history `moved` items, still present at the recorded
  Trash URL with the same fileID, inside a Trash folder. Permanently deletes
  them via the executor; records `freed` lines.
- Update `scripts/check-deletion-sites.sh` expectations? No: it already allows
  `CleanerActions/`.

## Open-files snapshot (from the 3.1 review)

`ProcessOpenFilesProvider` costs ~120 ms per call. Add
`Sources/CleanerActions/Liveness/OpenFilesSnapshot.swift`: an
`OpenFilesProvider` that takes one process/fd snapshot when created (reuse the
existing provider's scanning code by calling into it or extracting a shared
internal function inside `Liveness/` without changing its public behavior), and
answers `hasOpenFiles(under:)` from that snapshot. `Cleaner.run` takes a fresh
snapshot at the start of each run (and again every 500 items or 30 s, whichever
first). A failed snapshot answers `nil` (unknown → keep), never "no". Test it.

Note: another builder (3.2b) is changing `Action` (adds `.deletePermanently`),
`RootSpec`, `OwnerSpec` and `GateContext` (adds `rootOwners`) at the same time.
Build against what is on disk; treat any `Action` other than `.trash` as
"permanent only" in the executor path (requires `mode == .permanent` and
confirmation), so the merge is mechanical.

## Tests (`Tests/CleanerActionsTests/Clean/`)

Tests must not touch the real `~/.Trash`. Use a **fake `ItemExecutor`** that
moves items into a fixture folder `fixture/.Trash/` for most tests. Add one
integration test that uses `FileManagerExecutor` on an **attached disk image**
(create a 50 MB APFS sparse image under `build/test-fixtures/<uuid>/`, attach
with `hdiutil attach -nobrowse -mountpoint`, detach in teardown); if attaching
fails in the test environment, record `withKnownIssue`/skip with the reason.

Cases: allowed items move and are recorded; denied items recorded as skipped
with the reason; history write failure stops the run; permanent without
confirmation refused; nested parent+child order; preview equals run's gate
verdicts on unchanged state (rule 15); putBack success and each refusal (moved
again, path occupied, fileID changed); freeSpaceNow deletes only our items and
leaves a foreign file in the fake Trash; truncated history line tolerated.
