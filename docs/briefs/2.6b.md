## Problems seen (orchestrator review, 2026-11-06)

1. **False "nothing open" (dangerous).** `LivenessProviderTests.openFiles_anotherProcessHoldingAFileIsSeenForTheFileAndItsFolders`
   failed once on `main`: the provider said the file was open, then a moment
   later said its parent folder `logs` had **no** open files, while `tail -f`
   still held the file. A false `false` lets the gate allow an item that is in use.
2. **Stale "open" (safe but wrong).** `openFiles_ownHandleIsSeenAndThenReleased`
   failed once: after `close`, the provider still said `true`.
3. **Hang with ~1,400 idle dispatch threads.** Builder 3.3 saw one full
   `scripts/test.sh package` run hang for 30 minutes; a sample showed the main
   thread in `waitUntilExit` inside `LivenessProviderTests.Child.stop()` and about
   1,400 idle dispatch threads (thread explosion).
4. **CI cancel latency.** On the 3-core CI runner,
   `ScanEngineTests.cancellingTheStreamConsumerEndsPromptly` took 3.3 s against a
   200 ms budget (now hidden by `TC_TIMING_SLACK=10`; find the real cause).
5. **Duplicate logic.** `OpenFilesSnapshot` re-implements
   `ProcessOpenFilesProvider`'s inspection loop.

## Goal

Make open-file detection trustworthy, remove blocking waits from cooperative
threads, and make the test suite unable to hang.

## Work

- Reproduce 1 and 2 by running the liveness tests in a loop (`--filter
  LivenessProviderTests`, 50 iterations, and with `--parallel`). Find the cause
  (candidates: PID enumeration missing processes created/exiting during the walk;
  `proc_pidfdinfo` failures on fds that change while listing being treated as
  benign; path comparison with `/private` or firmlink prefixes; fd reuse in the
  test process). Fix it in **one shared inspector** (`Liveness/ProcessInspector.swift`)
  used by both `ProcessOpenFilesProvider` and `OpenFilesSnapshot`.
  Rule: any per-process failure other than `ESRCH` (process gone) or `EPERM`
  (not ours) must make the answer `nil` (unknown → keep), and a folder query must
  be answered from the same snapshot as a file query.
- Add a self-check: if the snapshot sees fewer than 50% of the PIDs that
  `proc_listpids` reported, return `nil`.
- Thread hygiene: find every blocking call that can run on the Swift cooperative
  pool (`DispatchSemaphore.wait`, `DispatchGroup.wait`, `NSCondition.wait`,
  `Process.waitUntilExit`, `Thread.sleep`) in `Sources/` **and** test helpers.
  Move each onto a dedicated thread or `DispatchQueue` that is not the
  cooperative pool, bridged with `withCheckedContinuation` (as `BulkWalker`
  already does), or replace it with an async API. Check `ReadOnlyCommand`,
  `OwnerProcess`, `WalkPool`, `OpenFilesSnapshot`, `LivenessProviderTests.Child`,
  and the `hdiutil` helpers in `CleanerActionsTests/Clean/`.
- Find why a GCD pool grew to ~1,400 threads (likely many concurrent blocking
  work items on a concurrent global queue); cap concurrency with a serial or
  `OperationQueue`-limited queue.
- Measure cancel latency under load: run `cancellingTheStreamConsumerEndsPromptly`
  and `BulkWalkerTests` cancellation while restricting CPU
  (`taskpolicy -c utility`, and `--parallel` with all tests). Fix the cause; the
  budget must hold without `TC_TIMING_SLACK` on this Mac under `--parallel`.
- `scripts/test.sh`: add a whole-run timeout (default 900 s, env
  `TC_TEST_TIMEOUT`) that kills `swift test`, prints "TIMEOUT", runs `sample` on
  the hung process for 3 s into `build/logs/test-hang-<ts>.txt` first, and exits
  non-zero.
- Tests: the existing liveness tests must pass 50/50 in a loop. Add a stress test
  (`openFiles_folderAnswersStayConsistentUnderChurn`): while a child holds a file,
  start and stop 20 short-lived processes and query file and folders 100 times;
  every answer must be `true` or `nil`, never `false`.
