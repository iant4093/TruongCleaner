# Brief 9.4: Review follow-ups (leftover contents, gate age walk budget)

You are builder-sonnet. Implement exactly this brief. Read `AGENTS.md` and the
steering files first; `safety.md` and `tech.md` always apply.

## Goal

Two open items from the 9.1 and 9.2 reports, closed before v1.0.0:

1. **Uninstall leftovers that hold data nobody can rebuild are not pre-selected.**
   Today `LeftoverMatcher` demotes a `.safe` user-scope folder to `.review` only
   from the names of its direct children, because `LeftoverFinder` never fills
   `LeftoverEntry.contents`. So `~/Library/Containers/com.docker.docker`, whose
   `Docker.raw` is nested at `Data/vms/0/data/Docker.raw`, is still `.safe` and
   pre-checked. Fix: after `LeftoverFinder` measures a user-scope folder candidate,
   apply the same warning rules using what it measured.
2. **The gate's age walk uses the shared thread budget.**
   `SafetyGate.newestModification(of:info:)` calls `BulkWalker.walk` directly with
   `maxWorkers: 2`, outside the process-wide budget (`tech.md`: one shared walker
   budget). Route it through the shared budget.

## Requirements

- REQ-UNI (see `docs/UNINSTALLER.md` §3): a folder with a VM or disk image, a non-empty
  `Data/Documents`, more than `LeftoverMatcher.largeFolderBytes`, or unreadable contents
  is `.review` with the matching `LeftoverWarning` in its evidence (`.withWarning`).
- `tech.md` Concurrency: bounded parallelism, one shared budget.
- `safety.md` rule 9: anything unmeasured or unknown keeps the stricter tier. Never
  promote `.review` to `.safe`.

## Design

1. In `CleanerCore/Uninstall/LeftoverMatcher.swift`, add a public static function, for example
   `reviewed(_ candidate: LeftoverCandidate, contents: LeftoverContents) -> LeftoverCandidate`
   (use the real candidate type name), that applies the existing private `warning(children:entry:)`
   logic for contents-only signals: if `candidate.tier == .safe` and contents show disk images,
   documents, or more than `largeFolderBytes`, set `.review` and wrap evidence in `.withWarning`.
   It must not double-wrap when the candidate already has a warning. Reuse, do not duplicate,
   the warning order in `warning(children:entry:)` (refactor that helper so both paths share it).
2. In `CleanerScanner/Apps/LeftoverFinder.swift`, step 3 (Measure), for each user-scope
   directory candidate that is still `.safe`:
   - `allocatedBytes` = the measured allocated bytes (already available).
   - `hasDocuments` = whether `<entry>/Data/Documents` lists at least one entry, read with
     `FolderReader` (no symlink follow). Missing folder = false. Read failure other than missing = nil.
   - `hasDiskImages`: compute during the same measurement walk if `BulkWalker`/`WalkResult` can
     give file names cheaply; if it cannot without per-file allocation, leave it nil and rely on size
     (Docker.raw is many GB). Say which you did in the report.
   - If measurement was partial (`isPartial`), treat the folder as `.review` with `.unreadable`.
   - Apply `LeftoverMatcher.reviewed(...)` and use the result's tier and evidence for the `Leftover`.
3. In `CleanerScanner/Walk/WorkerBudget.swift`, make `SharedBudgetWalk` (and its `walk`)
   `public` with doc comments. In `CleanerActions/Gate/SafetyGate.swift`,
   `newestModification` uses `SharedBudgetWalk.walk` with the same options. Keep the existing
   "nil when partial, denied or error" behavior. Cancellation while waiting for a lane returns nil
   (unknown means keep → `.deny(.unknownAge)`).

  (`allocatedBytes > 1 GB`, `hasDocuments == true`, `hasDiskImages == true`, all-small/empty) →

  No double `.withWarning`.
