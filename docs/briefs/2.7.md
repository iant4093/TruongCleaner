## Problem

`tcbench smartclean "$HOME"` takes 9.25 s on Ian's Mac (budget P4 < 5 s).
`user.caches` alone is 9.15 s: `~/Library/Caches` has 1.01 M files / 172 GB, at
~132k files/s. `installers.macOS` takes 3.1 s because it walks `/Applications`
(229k files) to find `Install macOS*.app`. `user.darwinTemp` takes 1.7 s.

## Goal

The user sees the full list of Smart Clean findings with sizes in under 5 s on
this Mac, without weakening any safety check.

## Work

1. **Glob without walking.** For `.glob` rules whose pattern's first component
   is a literal-with-wildcard at depth 1 (e.g. `Install macOS*.app`), list the
   root's direct children first and only walk matching children. Generalize:
   the engine walks only subtrees that can match the pattern.
2. **Parallel roots by size.** Today roots run `maxConcurrentRoots` at a time in
   request order. Start the largest expected roots first (use a cheap
   `getattrlistbulk` count of the root's direct children as a hint) so the long
   pole starts immediately, and let `user.caches`' children be walked as separate
   jobs that share the 8-thread budget (one walk per child folder is fine: it
   preserves per-child totals exactly).
3. **Stream per rule.** The engine already emits `ruleFinished` per rule; make
   Smart Clean show each section as soon as its rule finishes (if it waits for
   `.finished` today), with a determinate overall progress.
4. Re-measure with `tcbench smartclean "$HOME"` (3 runs) and `scripts/bench.sh`
   P4. Report before/after per rule.

Totals and findings must be identical before and after (add a test that runs
the old and new paths on a fixture home and compares findings and bytes).
