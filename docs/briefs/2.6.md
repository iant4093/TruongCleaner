# Brief 2.6: Measure the performance budgets

You are builder-sonnet. Implement exactly this brief. Read `AGENTS.md`, every
file in `.kiro/steering/`, and `docs/PLAN.md` §5 first.

## Goal

Numbers for budgets P1–P7 on this Mac, from repeatable scripts, so the README
and `docs/EVIDENCE.md` can cite them. Measurement only; fix nothing in the app
(report problems instead).

## Work

Add `scripts/bench.sh` (and small helpers under `scripts/bench/` if needed) that
builds Release once and then measures, writing JSON lines to
`build/bench/bench-<timestamp>.jsonl` and a Markdown table to stdout:

| ID | What | How |
|---|---|---|
| P1 | Cold launch to first window | Launch the Release app with `open -n -W`? No: start it with `open -n`, poll `CGWindowListCopyWindowInfo` (Swift helper) every 10 ms for a window owned by its PID; time from `open` to first on-screen window. 5 runs; report median and max. Quit with `pkill` between runs. |
| P2 | Idle CPU | After launch, wait 10 s, then sample `ps -o %cpu= -p <pid>` once per second for 30 s; report mean and max. Also `sample <pid> 3` and confirm no timer-driven stacks. |
| P3 | Memory idle / during full scan | `footprint <pid>` (or `vmmap --summary`) idle; during a scan use `tcbench walk /System/Volumes/Data --workers 8` peak RSS as the scanner number (the app's own scan peak can be read with `footprint` while launched with `-TCStartPage spacelens -TCAutoScan YES` on `~/Library`). |
| P4 | Smart Clean scan time (warm) | `tcbench scan-demo "$HOME"` is a subset; add `tcbench smartclean "$HOME"` that runs every enabled Safe/Review file rule from `Catalog.all` through `ScanEngine` (read-only) and prints total time. 3 runs, warm. |
| P5 | Full-scan throughput vs `du` | Reuse the S1 numbers if `spikes/s1-walker` still builds; otherwise `tcbench walk` vs `du -skx` on `~/Library`. |
| P6 | Bundle size | `du -sh` of the Release app and sizes of `dist/` after `scripts/package.sh`. |
| P7 | Main-thread stalls during a scan | Launch with `-TCStartPage smartclean -TCAutoScan YES`, run `spindump`? Not available without root; instead add an opt-in Debug-only `os_signpost` hang detector? No code changes allowed: use `sample <pid> 5` during the scan and report the share of main-thread samples outside `mach_msg`/run-loop waiting. |

All runs are read-only. Never press Clean, never run owner commands.
