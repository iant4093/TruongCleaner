# Brief 0.2: Spike S1, directory walker benchmark

You are builder-sonnet. Implement exactly this brief. Read `AGENTS.md`,
`.kiro/steering/safety.md` and `.kiro/steering/tech.md` first.

## Goal

Build a benchmark tool that compares ways to walk a directory tree and total
its allocated size, so the orchestrator can choose the scanner design (PLAN
D12, budget P5). You build it and smoke-test it on a small tree. The
orchestrator runs the full benchmark later, when nothing else is using the disk.

## Requirements

Informs REQ-SCAN-02, -03, -04, -06, -07 and REQ-PERF-03, -05.

## What to build

A SwiftPM package at `spikes/s1-walker/` (tools 6.4, macOS 26, Swift 6 mode,
`.treatAllWarnings(as: .error)`), one executable `s1walker`, no dependencies.

```text
s1walker --method <bulk|fm|fts> --workers <n> [--limit-seconds <s>] [--json] <root>
```

All three methods must:

- never follow symlinks and never cross into a different device ID than `<root>`;
- sum **allocated** size and count each file with link count > 1 once per `(device, fileID)`;
- count `EPERM`/`EACCES` directories separately (do not add them as 0 silently);
- keep no per-file objects (only counters and the hard-link set);
- stop when `--limit-seconds` passes and mark the result as partial.

Methods:

| Method | How |
|---|---|
| `bulk` | Darwin `getattrlistbulk(2)`. Request `ATTR_CMN_RETURNED_ATTRS`, `ATTR_CMN_NAME`, `ATTR_CMN_DEVID`, `ATTR_CMN_OBJTYPE`, `ATTR_CMN_FILEID`, `ATTR_CMN_FLAGS`, `ATTR_FILE_LINKCOUNT`, `ATTR_FILE_ALLOCSIZE`. Open directories with `openat(parentFD, name, O_RDONLY | O_DIRECTORY | O_NOFOLLOW)`. One reusable 256 KB buffer per worker. Parse with bounds checks; a malformed entry is counted as an error, never a crash. |
| `fm` | `FileManager.enumerator(at:includingPropertiesForKeys:options:)` with `.skipsPackageDescendants` off, prefetching `.isDirectoryKey`, `.isSymbolicLinkKey`, `.totalFileAllocatedSizeKey`, `.fileResourceIdentifierKey` (or `.fileIdentifierKey` on 26), `.linkCountKey`, `.volumeIdentifierKey`. For `--workers > 1`, split work by top-level subdirectory. |
| `fts` | `fts_open` with `FTS_PHYSICAL | FTS_XDEV | FTS_NOCHDIR`, using `fts_statp->st_blocks * 512`. For `--workers > 1`, split by top-level subdirectory. |

Workers: a bounded pool (a shared queue of directories for `bulk`; top-level
split for the others). Use Swift concurrency or `DispatchQueue.concurrentPerform`
/ threads, whichever you can make correct under Swift 6 strict concurrency.
Explain your choice in the report.

Output (one line, or JSON with `--json`): method, workers, root, files, dirs,
symlinks, hardlinkDupesSkipped, permissionDenied, otherErrors, allocatedBytes,
wallSeconds, filesPerSecond, peakRSSBytes (`getrusage` / `task_info`),
partial (bool).

Also add `spikes/s1-walker/run-bench.sh <root> [limit-seconds]`. It builds
Release, then runs each method with workers 1 and 8, plus `du -skx <root>`,
timing each with `/usr/bin/time -l`, and writes one JSON lines file to
`spikes/s1-walker/out/bench-<timestamp>.jsonl`. The orchestrator runs this
script; you only smoke-test it.

## Smoke test (you run this)

1. Create a fixture tree in `spikes/s1-walker/out/fixture/` with a small
   script `spikes/s1-walker/make-fixture.sh`: about 5,000 files over nested
   folders, some hard links (`ln`), a symlink to a folder outside the fixture
   (point it at `spikes/s1-walker/Sources` so following it would be visible),
   one folder with mode 000, sparse and empty files.
2. Run all three methods with 1 and 4 workers on the fixture. All must report
   the same file count and the same allocated bytes, matching `du -skx`
   (within 1 block per file rounding; explain any difference).
3. Run `run-bench.sh "$HOME/Library/Developer" 20` once to prove the script works
   on a real, read-only tree. Do not run it on bigger roots.
4. Restore the mode-000 folder's permissions so the fixture can be removed;
   you may remove `spikes/s1-walker/out/fixture/` when done.

## Safety

Read-only on everything outside `spikes/s1-walker/`. Do not write, move or
delete anything else. Do not run the benchmark on `/` or `/System/Volumes/Data`.

## Stop condition

Package builds in Release with zero warnings; smoke steps 1–3 pass; report written.

## Out of scope

Any code in `Packages/` or `src/`. UI. Tests in Swift Testing (spikes don't need them).

## Report format

1. Files changed. 2. Smoke results table (method × workers: files, bytes, seconds).
3. Every command run with exit code. 4. Deviations and why. 5. Open questions,
including anything surprising about `getattrlistbulk`.
