# Brief 0.3: Spike S3, Trash behavior

You are builder-sonnet. Implement exactly this brief. Read `AGENTS.md`,
`.kiro/steering/safety.md` and `.kiro/steering/tech.md` first.

## Goal

Find out which Trash API TruongCleaner should use (design §4 `TrashExecutor`,
REQ-CLEAN-01, -03, -04), using only a throwaway disk image so nothing lands in
the real `~/.Trash`.

## Setup (must use a disk image)

Write `spikes/s3-trash/run.sh`, which:

1. Creates `spikes/s3-trash/out/s3.sparseimage` (APFS, 300 MB) with `hdiutil create`
   and attaches it with `hdiutil attach -nobrowse -mountpoint spikes/s3-trash/out/vol`.
2. Runs the Swift tool below against that mount point only.
3. Detaches with `hdiutil detach` (also from a `trap` on exit).

On an attached volume, items moved to the Trash go to `<vol>/.Trashes/<uid>/`,
which is inside the image. **Before every trash call, the tool must check that
the item path starts with the mount point's real path and abort otherwise.**

## Swift tool

SwiftPM package `spikes/s3-trash/` (tools 6.4, macOS 26, Swift 6 mode, warnings
as errors), executable `s3trash <mountpoint>`. Link AppKit only for
`NSWorkspace.recycle`.

Measure and print as JSON lines to `spikes/s3-trash/out/results.jsonl`:

| Case | What to record |
|---|---|
| `FileManager.trashItem(at:resultingItemURL:)` on one file, one folder, one symlink (check the link moves, not its target) | resulting URL, whether it is under `<vol>/.Trashes/<uid>`, elapsed ms |
| `NSWorkspace.shared.recycle(_:)` on the same shapes | resulting URLs map, elapsed ms; note whether it needs a running app / main thread |
| Name collision: trash two items both named `same.txt` | resulting names |
| `fileID` before vs after the move (`URLResourceKey.fileResourceIdentifierKey` and `stat.st_ino`) | equal or not |
| Put Back metadata: after each method, list `<vol>/.Trashes/<uid>/` including hidden files and any `.DS_Store`; dump extended attributes of moved items (`listxattr`) | names of xattrs / files that could carry "Put Back" info |
| Moving back: `FileManager.moveItem` from the Trash URL to the original path | success, `fileID` unchanged |
| Throughput: 10,000 small files in 100 folders; trash the 100 folders one by one with each method | total seconds, per-item ms |
| Throughput: the same 10,000 files trashed one by one with `trashItem` | total seconds |
| Item with `chflags uchg` (user immutable) | error domain/code for each method |
| Item inside a folder you made read-only (`chmod 555` on the parent) | error for each method |

Make the tool fail closed: any unexpected path outside the volume aborts the run.

## Safety

Never call a trash or delete API on anything outside the mounted image.
Do not touch `~/.Trash`. Clear the `uchg` flag (`chflags nouchg`) and restore
permissions on your test items before detaching, so the image can be removed. You may delete `spikes/s3-trash/out/` contents when done,
except `results.jsonl` and a short `summary.md` you write there.

## Stop condition

`run.sh` runs end to end, detaches the image, and `out/results.jsonl` +
`out/summary.md` exist. `summary.md` gives a recommendation (which API, why)
with the numbers.

## Out of scope

`Packages/`, `src/`, any UI.
