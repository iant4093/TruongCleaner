You are builder-sonnet. Implement exactly this brief. Read `AGENTS.md`, every
file in `.kiro/steering/`, `docs/UI.md` §1, §4.2, §6, and the merged CleanerKit

## Goal

The main feature works end to end in the app: Scan → review grouped results →
Clean → result sheet with the real change in free space, Put Back and Free
Space Now.

## Part A: liveness (task 3.4) — `src/TruongCleaner/Platform/`

- `AppRunningAppsProvider: RunningAppsProvider`: for `.bundleID(id)` and
  `.childNameAsBundleID` (derive the ID from the item's first component below its
  root, as `ProcessNameOwnerProvider` does; reuse its helper if public), answer
  from `NSWorkspace.shared.runningApplications` read on the main actor (hop with
  `await MainActor.run`). For `.processName` return `.unknown` so the composite
  falls through to `ProcessNameOwnerProvider`.
- `LivenessProviders.make()` returns `CompositeOwnerProvider(first: AppRunningAppsProvider(), then: ProcessNameOwnerProvider())` and `ProcessOpenFilesProvider()`.

## Part B: models — `src/TruongCleaner/Pages/SmartClean/`

- `SmartCleanModel` (`@Observable @MainActor final class`):
  - `state: idle | scanning(progress) | results | cleaning(progress) | finished(CleanReport)`.
  - `scan()`: builds `Environment` (home = `FileManager.default.homeDirectoryForCurrentUser`,
    darwin dirs via `confstr(_CS_DARWIN_USER_CACHE_DIR / _CS_DARWIN_USER_TEMP_DIR)`, now),
    `ScanRequest(rules: enabled non-ownerCommand rules from Catalog.all, …)`, consumes
    the `ScanEngine` stream in a `Task`, and updates per-category sections live.
    Stop cancels the task.
  - Selection: Safe findings selected by default, Review not, Info never selectable.
    Per-row and per-category toggles. A computed "selected bytes" (allocated) and
    "at least" (private) pair.
  - `clean(mode:)`: builds a `CleanPlan` from the selection (with each rule's
    expanded roots from the scan), creates `Cleaner` with `FileManagerExecutor`,
    `HistoryStore(fileURL: ~/Library/Application Support/TruongCleaner/history.jsonl)`,
    and a `GateContext` factory; runs it off the main actor; shows progress.
  - `putBack(_:)` and `freeSpaceNow()` through `UndoService`.
- Settings needed now: `@AppStorage("deleteMode")` default `trash`.

## Part C: views

Follow `docs/UI.md` §4.2 exactly:

- Before scan: `PageHeader` + a short list of what is checked (category names
  from the catalog) + Scan button (`.buttonStyle(.glassProminent)`), also bound to
  the toolbar Scan button and ⌘R (wire the existing toolbar button in `RootView`
  to the current page's scan action via `AppModel`).
- Scanning: per-category rows with a `ProgressView` and live sizes; Stop button.
- Results: `Form(.grouped)` with one `Section` per category: header row with
  category toggle and total; rows for each rule with title, explain text
  (secondary), size, checkbox (`.toggleStyle(.checkbox)`); a `DisclosureGroup`
  listing up to 200 items (name, size, Reveal in Finder via
  `NSWorkspace.shared.activateFileViewerSelecting`). Review rows unchecked with a
  "Review" label; Info rows (if any) show size and no checkbox. Rows that hit
  `needsAccess` show `NeedsAccessRow` ("Needs Full Disk Access" + lock symbol;
  the button opens `x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`).
- Floating clean bar (`Components/CleanBar.swift`) at the bottom, in a
  `GlassEffectContainer`: "Move about X to the Trash" (or "Delete about X" in
  permanent mode) + `.glassProminent` Clean button (⌘⌫). With
  `accessibilityReduceTransparency`, use `.regularMaterial` and `.borderedProminent`.
- Confirm with `.confirmationDialog` listing per-category totals. Permanent mode
  shows a second confirmation naming the total size before `permanentConfirmed = true`.
- Result sheet: moved/deleted/skipped/failed counts; the measured change in
  available space beside the estimate (say plainly that items in the Trash still
  use space until it is emptied); a list of skipped items grouped by
  `DenyReason.userMessage`; buttons "Free Space Now" (confirm), "Done".
- All sizes via `ByteFormatter`; "about" for estimates.

`AppModel` holds `smartClean: SmartCleanModel`; `RootView` shows the page for `.smartClean`.

## Safety in the app

The app never calls a deleting API itself; everything goes through `Cleaner`
(checked by `scripts/check-deletion-sites.sh`). Do not run a real clean while
testing. You may run a **scan** of the real home (read-only) by launching the
app, but do not click Clean. Use `tcbench` or unit tests for the kit.

  `CleanerCore.Environment` explicitly.
