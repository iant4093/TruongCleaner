## Goal

Settings (⌘,), a real Full Disk Access status with the deep link, and a
once-a-day update check against GitHub Releases.

## Requirements

REQ-RULE-05, REQ-PERM-01 … -04, REQ-DIST-04, REQ-DIST-05.

## Part A: `AccessProbe` (kit, `Sources/CleanerScanner/Access/`)

```swift
public enum AccessState: Sendable { case granted, notGranted, unknown }
public enum AccessProbe { @concurrent public static func fullDiskAccess(home: URL) async -> AccessState }
```

Probe only these (S2 showed probing every container is slow): `~/Library/Safari`,
`~/Library/Mail`, `~/Library/Messages`, `~/Library/Containers/com.apple.stocks`
with `opendir`+`readdir` of one entry. `granted` if any is readable; `notGranted`
if every one that exists returns `EPERM`/`EACCES`; else `unknown`. Under 50 ms
total. Tests: inject the probe list and point it at fixture folders (one
`chmod 000`), check each verdict.

## Part B: Settings scene (`src/TruongCleaner/Pages/Settings/`)

`Settings { TabView { … } }` with tabs, each a grouped `Form`:

- **General**: Delete mode (`Picker`: Move to Trash / Delete immediately, with a
  caption explaining the second needs confirmation each time); "Check for
  updates automatically" toggle; "Check Now" button and last-checked time.
- **Exclusions**: list of folders (+ with `NSOpenPanel`, − to remove), stored in
  `~/Library/Application Support/TruongCleaner/exclusions.json` (array of paths);
  a `Settings` service exposes them to scans (`ScanRequest.userExclusions`) and
  gates (`PathPolicy(userExclusions:)`).
- **Rules**: one `Toggle` per category (`Category.allCases`) and a disclosure per
  category listing its rules with toggles. Disabled rule IDs persist in
  `@AppStorage("disabledRules")` (JSON array). Expose `enabledRules` for scans.
- **Permissions**: Full Disk Access state (granted / not granted / unknown with a
  plain explanation of each), "Open Privacy Settings" (deep link
  `x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`;
  if `open` returns false, open `x-apple.systempreferences:com.apple.preference.security`
  and show "Find TruongCleaner under Full Disk Access"), "Check Again". Note that
  after an update the permission may need to be granted again (ad-hoc signing).

Re-probe access when the app becomes active (`scenePhase` change to `.active`)
and publish it on `AppModel.access`; pages already showing `NeedsAccessRow` can
read it.

## Part C: update checker (`src/TruongCleaner/App/UpdateChecker.swift`)

- `GET https://api.github.com/repos/iant4093/TruongCleaner/releases/latest` with
  `URLSession.shared` (ephemeral configuration, no cookies), `Accept:
  application/vnd.github+json`, 10 s timeout, at most once per 24 h (store the
  last check date) and only if the toggle is on.
- Parse `tag_name` (`build-N`) and `name`; compare N + 1000 with the running
  `CFBundleVersion`. If newer, show a banner at the top of the Overview page:
  "TruongCleaner Build X is available" with buttons "Copy Install Command"
  (`curl -fsSL https://github.com/iant4093/TruongCleaner/releases/latest/download/install.sh | sh`)
  and "View Release" (opens `html_url`). Dismiss hides it until the next build.
- No other network requests anywhere in the app (REQ-DIST-05). Failures are silent
  (logged with `Logger`).
- Make the parser a pure function and test it in the package? It lives in the
  app; keep it in the app but small. (No app test bundle yet.)
