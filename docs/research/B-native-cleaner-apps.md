## 1. Pearcleaner (Swift, app uninstaller + orphans + developer cleaner)

### 1.1 Architecture
- Sidebar "pages" (`CurrentPage` enum): Applications, Developer, File Search, Homebrew, Lipo, Orphans, Packages, Plugins, Services, Updater. Users can hide pages in Settings.
- Targets in the Xcode project: main app, `PearcleanerHelper` (privileged XPC daemon), `PearcleanerSentinel` (login agent that watches the Trash), `FinderOpen` (sandboxed Finder extension), a CLI (`pear`), and deep links (`pear://`).
- Dependencies: Sparkle >= 2.8.0 (used to update *other* apps in its Updater page), swift-argument-parser, and the author's own `AlinFoundation` package (tracked on a branch, not a version).

### 1.2 Directories searched for an app's leftovers (exact list from `Locations.swift`)
Home (`~`) entries, each listed directly (depth 1):
`~`, `~/.config`, `~/Documents`, `~/Desktop` (Steam shortcuts), `~/Applications`, `~/Library`,
`~/Library/Application Scripts`, `~/Library/Application Support`, `.../Application Support/CrashReporter`,
`.../Application Support/Steam/steamapps` and `.../steamapps/common`,
`.../Application Support/com.apple.sharedfilelist/com.apple.LSSharedFileList.ApplicationRecentDocuments`,
`~/Library/Containers`, `~/Library/Caches`, and these named cache folders: `Caches/com.apple.helpd/Generated`, `com.crashlytics`, `com.google.SoftwareUpdate`, `com.google.Keystone`, `org.sparkle-project.Sparkle`, `com.segment.analytics`, `SentryCrash`, `Rollbar`, `Amplitude`, `Realm`, `Parse`,
`~/Library/Group Containers`, `~/Library/HTTPStorages`, `~/Library/Internet Plug-Ins`, `~/Library/LaunchAgents`, `~/Library/Logs`, `~/Library/Logs/DiagnosticReports`, `~/Library/Preferences`, `~/Library/Preferences/ByHost`, `~/Library/PreferencePanes`, `~/Library/Saved Application State`, `~/Library/Services`, `~/Library/WebKit`.
System: `/Applications`, `/Users/Shared`, `/Users/Library`, `/Users/Shared/Library/Application Support`, `/Library`, `/Library/Application Support`, `/Library/Application Support/CrashReporter`, `/Library/Caches`, `/Library/Extensions`, `/Library/Internet Plug-Ins`, `/Library/LaunchAgents`, `/Library/LaunchDaemons`, `/Library/Logs`, `/Library/Logs/DiagnosticReports`, `/Library/Preferences`, `/Library/PrivilegedHelperTools`, `/private/var/db/receipts`, `/private/tmp`, `/usr/local/{bin,etc,opt,sbin,share,var}`.
Per-user Darwin dirs: the `_CS_DARWIN_USER_CACHE_DIR` and `_CS_DARWIN_USER_TEMP_DIR` folders (under `/private/var/folders`).
Dynamic: every immediate subfolder of `~/Library/Application Support` is added as its own search root, so vendor folders are searched one level deeper.

Depth rules: `~/Library` and `/Library` are searched to **depth 2** (to find vendor folders like `/Library/Objective-See/LuLu`); all other roots to depth 1. At depth 2, if the parent is not one of the standard Library subfolders (a set of 18 names: Application Scripts, Application Support, Caches, Containers, Group Containers, HTTPStorages, Internet Plug-Ins, LaunchAgents, LaunchDaemons, Logs, Preferences, PreferencePanes, PrivilegedHelperTools, Saved Application State, Services, WebKit, Extensions, Frameworks), the whole vendor parent folder is offered instead of the child.
A `skipDeepSearch` set (about 130 names) stops depth-2 descent into Apple-owned Library folders: Apple, Audio, Bluetooth, ColorSync, Keychains, Mail, Messages, Mobile Documents, Photos, Safari, Cookies, CloudStorage, Developer, Python, Ruby, Java, Fonts, Sounds, Spotlight, Receipts, Shortcuts, and `com.apple.*` service bundles.

Extras beyond directory listing:
- **Containers by UUID**: UUID-named folders in `~/Library/Containers` are matched by reading the `MCMMetadataIdentifier` key in each folder's hidden `.com.apple.containermanagerd.metadata.plist`. Group containers come from `containerURL(forSecurityApplicationGroupIdentifier:)`.
- **Spotlight supplement** (`NSMetadataQuery`, user-home scope, 5 s timeout, capped at 500 results). Strict mode: exact display-name equals app name or bundle ID. Enhanced: contains match on display name or path. Deep: also comment, creator, copyright, encoding application, optional text content, and all words of multi-word names.
- **Entitlements**: the app's entitlement values (e.g. group IDs) are used as extra match strings.
- **Steam games**: desktop shortcuts and `appmanifest_<id>.acf` are matched by the game ID read from the launcher script.
- **Web apps / wrapped apps**: handled with their own branches.
- **Previously found "zombie" files** associated with the app are re-added if still on disk.

### 1.3 Matching heuristics
- Normalization (`pearFormat`): strip everything that is not alphanumeric, lowercase. If the result is empty, keep the original.
- Identifiers cached per app: formatted bundle ID, last two bundle-ID components joined, formatted name, name with trailing version digits removed (e.g. "Bartender 6" to "bartender"), letters-only name, the `.app` file name, company name (the middle part of a 3-component bundle ID), team identifier, entitlements, and a "base bundle ID" (bundle ID minus a final `helper|agent|daemon|service|xpc|launcher|updater|installer|uninstaller|login|extension|plugin`).
- Three user-selectable **sensitivity levels**. Strict (default): exact equality for name, path name, letters-only name, entitlements. Enhanced: adds "contains" matches, two-component bundle-ID match, version-stripped name. Deep: adds company name, team ID, and the wide Spotlight metadata query ("may find other apps by the same developer").
- Full bundle-ID "contains" is checked at every level (if the bundle ID is valid; a single-component ID must be at least 5 characters).
- **Per-app rules table** (`conditions`, about 26 entries): keyed on bundle ID, with `include` strings, `exclude` strings and `includeForce` / `excludeForce` absolute paths. Examples of what it encodes: Xcode vs Xcodes.app vs XcodeCleaner exclude each other; Chrome excludes "iterm", "chromefeaturestate", "monochrome"; Edge excludes vscode/office; Firefox vs Thunderbird exclude each other; VS Code vs VS Code Insiders; JetBrains forces `Application Support/JetBrains`, `Caches/JetBrains`, `Logs/JetBrains`; Arc forces `Application Support/Arc` and `Caches/Arc`; Logi Options excludes "login" and "logic".
- **Skip rules** (`skipConditions`): skip names starting with mobiledocuments, reminders, dsstore, comapplepasswordmanager (with an allow-list of Apple developer-tool prefixes); skip `~/.Trash`, `/Library/SystemExtensions`, and the Apple Password Manager native messaging manifests for Chrome and Chromium.
- User exclusion list (folders chosen in Settings), applied to every candidate; results are then de-duplicated so a child path is dropped when its parent is already in the list.
- Sizes: Spotlight `kMDItemLogicalSize` for files and bundles; manual on-disk walk for plain directories (because Spotlight is unreliable for them).

### 1.4 Orphaned-file detection (`ReversePathsFetch.swift`)
- Scans the "reverse" list only: `~/Library/{Application Scripts, Application Support, Application Support/Caches, ...RecentDocuments, Containers, Caches, HTTPStorages, Internet Plug-Ins, LaunchAgents, Logs, Preferences, PreferencePanes, Preferences/ByHost, Saved Application State, WebKit}`, `/Users/Shared/Library/Application Support`, `/Library/{Application Support, Application Support/CrashReporter, Internet Plug-Ins, LaunchAgents, LaunchDaemons, PrivilegedHelperTools}`.
- Each entry is flagged if: it is not a 32-hex-character UUID name; its normalized name does not contain any term in a large `skipReverse` list (about 230 substrings, e.g. apple, dock, icloud, cloudkit, webkit, homebrew, microsoft, mozilla, google, sparkle, sentry, spotlight, crashreporter, caches); it has a supported file type; and **no installed app is related**.
- "Related to an installed app" = the normalized path contains an installed app's formatted bundle ID, name or entitlement string, each at least 5 characters long (a deliberate guard against short names matching everything); for `/Containers/` paths the container's real bundle ID is also compared. Per-app `conditions` can also exclude.
- This is a pure substring test. No ownership proof (no code-signing or receipt check).
- Streaming results in batches of 10; a stop flag exists.
- The skip list is why entries like `group.is.workflow` (Shortcuts) and `org.cups.PrintingPrefs` are reported as orphans in open issues #617 and #610: they are not covered by it.

### 1.5 Other cleaning surfaces
- **Developer page** (dev environment cleaner): per-tool path tables with `*` wildcards, for Android Studio, Cargo, Carthage, CocoaPods, Composer, Conda, Cursor, Deno, Go modules, Gradle, Haskell Stack, IntelliJ, Maven, Nix, npm/pnpm/bun, pip, Poetry, Pub, pyenv, Ruby gems, SwiftPM, uv, VS Code, Xcode (DerivedData, Archives, CoreSimulator Devices, DeviceSupport for iOS/tvOS/watchOS/macOS, DocumentationCache, UserData), Yarn, Zed. Several entries are *user data*, not caches: `~/.vscode/extensions`, `Application Support/Cursor/User`, `~/.cargo`, `~/.pyenv`, `~/.nvm`, `~/anaconda3`.
- **Lipo** (strips architectures from universal apps), **translations pruning** (removes unused `.lproj`), **PKG manager** (reads receipts through the private `PackageKit` receipt class), **Services**, **Plugins** (a table of 20 plug-in folder kinds: Audio Components/VST/VST3/CLAP/HAL, PreferencePanes, QuickLook, Screen Savers, Internet Plug-Ins, CoreImage, ColorPickers, Fonts, Dictionaries, Automator, Safari Extensions, Motion Templates, Spotlight importers, Services, Address Book, Contextual Menu, Input Methods, Widgets), **Homebrew manager** (reads cask `uninstall` stanza keys such as `pkgutil`, `launchctl`, `login_item`, then runs `pkgutil --files` and `pkgutil --forget` through the privileged path), **Apps Updater** (Sparkle feed discovery via `SUFeedURL`, App Store, Homebrew).
- **Sentinel**: an `SMAppService.agent` that uses FSEvents on `~/.Trash`; when an `.app` lands in the Trash it opens `pear://openApp?path=...` so the leftover search starts automatically (roughly 2 MB RAM, per README).

### 1.6 Privileged operations, permissions, distribution
- Helper: `SMAppService.daemon` (register once, user approves in Login Items). Mach service with `.privileged` XPC. The helper exposes `runCommand(command:)`, which runs **an arbitrary string through `/bin/bash -c` as root**, plus two Mach-O thinning calls. Client validation compares the app's code-signing **certificate chain** with the caller's (a pattern credited in the source to Erik Berglund's SMJobBless example); it does not check the identifier or team ID, so any binary signed with the same certificate is accepted (my reading of the code).
- The old `AuthorizationExecuteWithPrivileges` path was removed (Settings text says Apple deprecated it). There is an optional stored-password path (`KeychainPasswordManager`, `PasswordRequestHandler`) used before the helper existed; issue #496 complains of a password prompt on every delete.
- Not sandboxed. The main app's entitlements contain only an app group. Only the Finder extension has `app-sandbox`.
- Full Disk Access detection: three probes in order, `~/Library/Containers/com.apple.stocks`, `~/Library/Safari`, `~/Library/Mail`; each tried with `access(R_OK)` then a directory listing; two attempts with 100 ms gap. A separate status line also reads `/Library/Application Support/com.apple.TCC/TCC.db`.
- Distribution: Developer ID (`ExportOptions.plist`: method `mac-application`, manual signing). Releases on GitHub; `brew install --cask pearcleaner`. The repo has no build/notarize workflow (only an issue-template closer), so the release pipeline is not public. The app's own updater is the author's `Updater(owner:repo:)` from AlinFoundation, which reads GitHub releases (implementation not read).
- Security note: the README says a fake `pearcleaner.com` served malware; issues #585, #588, #592, #595, #603, #608 report it. Lesson: a popular OSS cleaner becomes a phishing target.

### 1.7 Deletion method, undo, safety
- Not `trashItem` and not `NSWorkspace.recycle`. It builds `mkdir` and `/bin/mv` shell commands and runs them (through the helper when any item is not writable, else a direct shell), moving items into **`~/.Trash/<AppName>_<yyyy-MM-dd_HH-mm-ss>/`**, adding `-N` suffixes on name collisions.
- Undo: an `NSUndoManager` action plus a persistent history of (original, trashed) pairs (`UndoHistoryManager`, shown in a Delete History view). Restore uses `mv` back and `rmdir` of the bundle folder. Finder's "Put Back" is not supported.
- Path guard before deletion: refuses `/`, `/Applications`, `/Library`, `/System`, `/usr`, `/bin`, `/sbin`, `/etc`, `/var`, `/private`, `/opt`, the home folder, and the user's configured app folders. It does not check SIP-protected objects or sync folders.
- Selection: everything found is selected by default for Apps; there is a first-use warning sheet for leftover files (changelog 3.7.0). Orphans are shown for the user to pick.

### 1.8 UI patterns
- Left sidebar of tool pages, app list (list or grid, user/system sections, sort by name or size), right detail view with file rows grouped by category, size per row, icons, per-app sensitivity override, a "console" log panel streaming scan steps, theme colors, Finder right-click extension, menu bar/CLI/deep links.

### 1.9 User complaints and data-loss issues (open unless noted)
- #587 Uninstalling OpenSCAD deletes `~/Documents/OpenSCAD` (user models and source). The `~/Documents` root is in the search list.
- #571 Chrome uninstall removed an unrelated user folder whose name began with "chro...".
- #506 Uninstalling Firefox Nightly deleted the shared `~/Library/Application Support/Firefox` (stable Firefox profiles, bookmarks, passwords).
- #618 Uninstalling Pixelmator Pro (bundle ID `com.apple.pixelmator`) moved 3,874 items, including 468 preference files, 865 containers and 183 group containers of unrelated Apple apps. Cause is the Apple-bundle-ID prefix matching `com.apple` data.
- #538 Orphans and Lipo "scrape too much and break apps" (Autodesk, CrossOver, Adobe).
- #477 Orphan cleanup deleted most apps' data in Application Support (restored from Trash). #143 (closed): Zen Browser data lost during orphan cleanup. #494 (closed): deleting one browser broke an iCloud Passwords extension in another.
- #616 A system-owned QuickLook container was moved into the Trash bundle folder and then could never be deleted (System Policy deny), making Empty Trash fail permanently.
- #617 / #610 Apple Shortcuts and CUPS preference folders flagged as orphans.
- #600 "Can't use on macOS 27"; #577 Liquid Glass renders incorrectly on macOS 27 beta.
- #575 Lipo strips `arm64e`. #496 password prompt on every delete. #589 exits when launched from Raycast or `open`.

## 2. Lemon Cleaner (Tencent, Objective-C)

### 2.1 Architecture
- Modules from README: Lemon (main), LemonMonitor (menu bar stats), BigOldFile, DuplicateFile, PhotoClean (similar photos), Uninstaller, PrivacyClean (browser privacy), LoginItemManager, SpaceAnalyse, FileMove, Hardware, NetSpeed, and the `LemonClener` cleaner library (`libcleaner`). Plus `Tools/LemonDaemon` (root daemon) and PrivacyProtect.
- No `.github` folder, so no public CI. No Sparkle. The update mechanism for the app itself is not in the source (not verified).

### 2.2 The cleaning rule file (data-driven XML)
- Bundled rules: `LemonClener/LemonClener/libcleaner/garbage1_en.xml` / `_zh.xml` (361 lines, version "2024.03.21.1") and a reduced `garbage_appstore_*.xml` (227 lines) for the Mac App Store build.
- **A downloaded override exists**: if `~/Library/Application Support/com.tencent.lemon/KnowledgeEn/2` (or `KnowledgeCh/2`; `com.tencent.LemonLite/...` for the App Store build) exists, it is parsed instead of the bundled XML; a parse error deletes it. This is how the product's "hundreds of apps" rule set is delivered. **That full rule set is not in the repo**: the open XML has only Xcode and Sketch under Application Junks. The code that downloads the Knowledge file was not found in this repo (not verified).
- The uninstaller has its own small `uninstall.xml` (version 2019.12.30.1, bundle-ID keyed folder-name overrides such as `<application_support name="...">`) and `json_setting.json` (stub: only `{"version":1,}`) next to `json_setting.qce`, a 475 KB opaque binary blob that holds the real per-app predefined paths (appears encrypted or compressed; not decoded).
- **XML structure**:
  - `<filters>`: numbered `<filter id column relation value action>`. Columns seen: bundleid, app, filename, filepath, filesize, time, subfilecount, subfilepath, laungeuagekey (sic). Relations: is, begin with, end with, contains, match (regex), greater, smaller. Action: include or exclude. 87 filters in the shipped file.
  - `<category id>` containing `<item id recommend fastmode defaultstate showaction showresult bundleid>` (an item with `bundleid` is only shown when that app is installed).
  - `<action type=... clean=... appversion apppath sandbox cleanemptyfolder cleanhiddenfile>` containing `<atom filters="(7+68+69+72)">` (a boolean expression over filter IDs: `+` and, `|` or, parentheses) and `<path type="abs|special" level="-1|0|1" value=... filename="regex" value1=...>`. `special` types include `SystemTempDir` (per-user `/var/folders` temp) and `FireFoxProfiles`. Level semantics (recursion depth) not verified.
  - Action types in the parser: file, dir, language, leftcache, leftlog, brokenregister, brokenplist, appleft, binary / otherBinary (architecture thinning), InstallPackage, developer, mail, soft, appcache, derivedapp, archive, and WeChat avatar/image/image90/file/video/audio. Clean modes: remove, movetrash, cutbinary, deletebinary, deletepackage, truncate, removelogin, removelanguage, safaricookies, DB record.
  - `<cautions>` list items that trigger a warning before cleaning.
- **Categories and representative paths in the shipped XML** (paths as written; `~` is the home):
  - *System Junks*: System Caches (`/Library/Caches`); System Logs (`/Library/Logs`, `/Library/Logs/DiagnosticReports`, `/private/var/log/asl`, `/private/var/log/DiagnosticMessages`, `/private/var/log/cups`, `/private/var/log`, `/private/var/db/diagnostics`; log files filtered by size over 10,000 bytes or names like `access.log*`, `*.out`, `*.log.*`); Unneeded Language Files (`.lproj` inside `/Applications/*.app`, keeping `en` and `zh`, skipping Apple, Microsoft, Xcode, 1Password, IINA and browsers); iOS Photo Caches (`~/Pictures/iPod Photo Cache`); iOS Update Caches (`*.ipsw` under `~/Library/iTunes`); iOS Device Backup (`~/Library/Application Support/MobileSync/Backup`, not recommended); Trash (`~/.Trash`, not recommended, can clean empty folders and hidden files); Download (`~/Downloads`, not recommended).
  - *Application Junks*: Xcode (app caches `~/Library/Caches/com.apple.dt.Xcode` and the temp dir; DerivedData; iOS and macOS DeviceSupport; Archives `*.xcarchive`; device logs; DocumentationCache; `~/Library/Developer/CoreSimulator`; simulator runtimes under `/Library/Developer/CoreSimulator/...`, with a call to `xcrun simctl runtime delete`), Sketch (caches, logs, `/.DocumentRevisions-V100`).
  - *Internet Junks*: Mail attachments (`~/Library/Containers/com.apple.mail/Data/Library/Mail Downloads`, plus Mail scanner), Safari (`~/Library/Caches/com.apple.Safari`, `Caches/Metadata/Safari`, `Containers/com.apple.Safari.CacheDeleteExtension`, `Caches/com.apple.Safari.SafeBrowsing`, `Caches/com.apple.safaridavclient`), Chrome (`~/Library/Caches/Google/Chrome/Default/Cache`), QQBrowser, Opera (version-gated actions using `appversion` regex), Firefox (`~/Library/Caches/Firefox`), Edge (`~/Library/Caches/Microsoft Edge/Default/Cache`), Download Logs (`~/Library/Preferences/com.apple.LaunchServices.QuarantineEventsV2`).
  - Hard-coded exclusion filters worth noting: Apple bundle IDs, Microsoft, `com.apple.appstoreagent` cache (excluded because cleaning broke the App Store updates list on macOS 15), Aerial wallpaper cache, ColorSync, Desktop Pictures, Logic Pro, 1Password and IINA language packs, and WeChat/QQ/DingTalk containers.
- Other Lemon features: big files (over 50 MB), duplicate files, similar photos, space analysis, file move, browser privacy, login-item manager, hardware and temperature monitor.

### 2.3 Uninstaller: where it looks and how it matches (`LMLocalApp.m`, `LMSearchPath.m`)
- Scan order: predefined (per-app) paths, `pkgutil` receipt contents, then: bundle(s), kexts, file systems, preference panes, login items, Application Support, Caches, Preferences, Saved Application State, crash reports, Logs, Sandboxes (Containers), Launch daemons, Others. Results are de-duplicated (parent beats child; later groups lose to earlier ones).
- Exact roots per group:
  - Support: `/Library/Application Support`, `~/Library/Application Support`
  - Caches: `/Library/Caches`, `~/Library/Caches`, `NSTemporaryDirectory()` and its sibling `C` folder
  - Preferences: `/Library/Preferences`, `~/Library/Preferences`
  - State: `~/Library/Saved Application State`
  - Crash: `/Library/Application Support/CrashReporter`, `/Library/Logs/DiagnosticReports`, and the `~` equivalents
  - Logs: `/Library/Logs`, `~/Library/Logs`
  - Sandboxes: `~/Library/Containers` (bundle-ID match; plus any container whose `Container.plist` `SandboxProfileDataValidationInfo` lists an `application_bundle` or `application_dyld_paths` under the app's path)
  - Launch: `/Library/LaunchAgents`, `/Library/LaunchDaemons`, `/Library/StartupItems`, `~/Library/LaunchAgents`, `~/Library/LaunchDaemons`
  - Others: `/Library`, `~/Library`, `/Users/Shared`, `~/Library/WebKit` (items here are **unselected by default**; all other groups are preselected unless they come from the predefined list)
- Matching: names are lowercased with spaces removed. Whole-name regex match (not substring) for app name, executable name and display name: `name` optionally followed by `.something`. Bundle ID regex: optional single prefix word plus the full bundle ID plus optional suffix. Company-name step: for 3-part bundle IDs, a folder named for the company is opened and only children matching name/bundle ID are taken. Crash reports additionally require a `_<uuid-or-date>` suffix. Optional XML override per bundle ID gives an extra folder name per group.
- Launch plists: exact bundle-ID match, plus a fuzzy filename match that is accepted only if the plist's `Program` or `ProgramArguments` points at a path already found for the app.
- A source comment records a past bug (FinalShell, whose bundle ID is `st`): substring matching on short bundle IDs matched every launch plist and deleted all background services. The fix was the whole-name regex. Matching on `~/Documents`, `~/Desktop` etc. is commented out.
- Special cases: VMware Fusion VMs (`~/Virtual Machines.localized/*.vmwarevm`), Android Studio recent projects, MacBooster, JetBrains.
- Package receipts (`pkgutil --files <id>` plus a script that finds the install prefix): builds a tree from the receipt, then proposes deleting a *folder* only when `pkgutil` lists every item that is actually in it; otherwise only the listed files. A protected list (`/`, `/Library`, `/Library/Filesystems`, `/Library/Extensions`, `/System`, `/Applications`, `/bin`, `/cores`, `/sbin`, `/usr`, `/Library/PreferencePanes`, `/Library/LaunchAgents`, `/Library/LaunchDaemons`, and the home equivalents) is never proposed whole. A keyword filter can limit to names containing the app name. Receipt removal uses `pkgutil --forget` through the daemon.
- Orphans ("uninstall leftovers" scan): `QMAppLeftScan` / `QMAppUnlessFile` in `libcleaner/QMSpecialClean`. Not read in depth.

### 2.4 Privileged operations
- Root LaunchDaemon `com.tencent.LemonDaemon` (plist in `Lemon/PreLaunch`: KeepAlive, RunAtLoad, global Mach service), binary at `/Library/Application Support/Lemon/LemonDaemon`. Installed by the app through `STPrivilegedTask` (a wrapper over `AuthorizationExecuteWithPrivileges`) and AppleScript via Finder. No `SMAppService` or `SMJobBless` (the grep hits were only STPrivilegedTask and a login-item manager).
- Daemon API (XPC plus a pipe protocol): file removal (permanent, move to a user's Trash, truncate, cut binary), kill by pid or keyword, `task_for_pid`, kext management, pkg receipt forget, update hooks.
- **The listener accepts every connection** (source comment: "TODO: xpc authorization"; it logs the client's path and only uses the name to decide which interface to attach). Issue #148 (closed) reports that any local process could use the root service. Treat as the main anti-pattern.
- Entitlements for the direct build: `automation.apple-events` and `personal-information.photos-library`. No `app-sandbox`, so the Developer-ID-style build is unsandboxed. A separate App Store target (`Lemonas`, `isAppStoreVersion` branches) has no daemon and uses plain `removeItemAtPath`.
- Full Disk Access: macOS 10.14+, `QMFullDiskAccessManager` tries to list `~/Library/Safari` and read `Safari/LastSession.plist` or `Bookmarks.plist`; denied means unauthorized. UI: a pop-up page before scanning, with a deep link to settings.

### 2.5 Deletion method, safety
- Cleaner default (`McCleanRemoveRoot`) is **permanent delete by the root daemon**. Only items flagged movetrash or deletepackage go to the user Trash (daemon renames into `~/.Trash` "like Finder"). The App Store build deletes permanently in-process.
- Duplicate and large-file cleanup asks Finder (AppleScript) to trash; when Finder automation is not authorized it **falls back to permanent deletion** while the UI says "moved to Trash" (issue #149, open).
- Per-item `recommend` (YES/NO), `defaultstate`, `fastmode` flags drive default selection; risky items (Trash, Downloads, device backups) are never recommended. `<cautions>` entries warn before cleaning.
- A scan-size cache exists (`QMScanFileSizeCacheManager`).

### 2.6 UI
- Single main window with a big circular progress/size ring, animated scan screens (image sequences), a result view with a collapsible tree of categories, items and files, per-row checkbox, reveal-in-Finder, and a "fast mode". A menu bar monitor (CPU temperature, fan, network, memory) is a separate app. Localized zh-Hans and en.

## 6. Features worth adopting in TruongCleaner

1. **Evidence-ranked leftover matching with reasons and confidence** (certain / likely / possible). Show the reason on every row; preselect only certain/likely items that no other installed app claims. (Peel)
2. **Rival detection**: before offering a file, check whether another installed app, or an app Launch Services knows about on another disk, has an equal or stronger claim; mark such files shared and unselected. Include sibling-app handling (Firefox/Nightly, Chrome/Canary). (Peel)
3. **Judge launch jobs by the program they run**, not by file name; accept a fuzzy-named plist only if its `Program` / `ProgramArguments` points into already-found app paths. (Peel, Lemon)
4. **Read identifiers from the files themselves**: container metadata plist (`MCMMetadataIdentifier`), `Container.plist` bundle paths, plug-in declared identifiers, entitlements/app groups, team ID. (Pearcleaner, Lemon, Peel)
5. **A protected-data list in a shared module that the helper also enforces**, covering iCloud/CloudStorage, Keychains, Mail, Messages, Safari, Photos, Apple group containers by name pattern, dotfiles/credentials, wallet keys, media libraries, synced folders. Judge paths as written, as resolved, and by device+inode. (Peel)
6. **Pure, unit-tested safety guard** that every delete passes: operation size cap, SIP/protected prefixes, firmlink canonicalization, symlink-redirect check, user exclusions. (Mac Sai, Peel)
7. **Move through an open directory descriptor** and re-check the kernel's name for the folder, to close the check-then-move race. (Peel)
8. **Bundle-ID-only orphan detection** with helper-suffix stripping, dotted-prefix lineage against installed IDs, a never-flag prefix list (Apple, Chromium/CEF, Qt, Electron, Google Keystone), and automatic orphan removal limited to Caches/Logs/HTTPStorages/Saved State/WebKit. Show name-only matches as "review", never preselected. (Mac Sai)
9. **Trash-first deletion with a persistent History** that stores original path, trashed path and file identity; restore only the same item from a real Trash; write a per-item journal so a crash still reaches History; flag the few non-undoable actions before confirming. (Peel, Pearcleaner)
10. **Allow-list, not just a block-list, for "cleanup" categories** (Purge), with a visible reason when something is skipped.
11. **Per-item plain-language explanation and safety label** and a "why this file belongs" line. (Purge, Peel)
12. **Open-file / in-use check** before and during removal; leave items held by running programs and say which program. (Peel)
13. **Data-driven rule file** for junk categories, modelled on Lemon's structure: filters with column/relation/value/action, boolean combination of filters per action, per-item `recommend`/default-state flags, `bundleid` gating (only show if the app is installed), `appversion` regex gating, and a remote-updatable override file with validation and fallback to the bundled one. Do this in a signed JSON or plist format rather than XML. (Lemon)
14. **Developer cache catalog** per tool with wildcard paths (Xcode: DerivedData, Archives, DeviceSupport, simulators, DocumentationCache, UserData/Previews; Gradle, Maven, npm/pnpm/bun, Cargo, pip/uv, Go, CocoaPods, Carthage, SwiftPM, Docker/OrbStack), with an "in use by this IDE" owner so IDE data is not treated as orphaned. (Pearcleaner, PureMac, Peel)
15. **Package-receipt-aware removal**: list a receipt's files with `pkgutil`, propose a folder only when the receipt lists everything in it, never propose protected system folders, and move receipt files to the Trash instead of `pkgutil --forget`. (Lemon, Peel)
16. **Helper design**: `SMAppService.daemon`, Mach service, XPC with a code-signing requirement on the team ID and identifier, no shell, fixed operations, fixed folder allow-list, root-only ledger, protocol-version check, spawn constraint in the launchd plist. (Peel, Purge)
17. **Real-read FDA probe** (read a file or list a directory in a TCC-protected location; do not use `fileExists` / `isReadableFile`) so the app also appears in the FDA list; retry the failed operation once FDA is granted. Probe `~/Library/Safari`, `~/Library/Mail` and the TCC database. (PureMac, Pearcleaner, Lemon)
18. **Trash watcher** (FSEvents on `~/.Trash` through a login agent) that offers to clean leftovers when an app is dragged to the Trash. (Pearcleaner Sentinel)
19. **UI**: sidebar of tools with Home overview; list rows with kind, size, reason, checkbox and a held-back banner; a single bottom "Move to Trash" bar; a selection that persists across pages; scan progress log; Finder extension and CLI that share the core package. (Peel, Pearcleaner, Purge)
20. **Release pipeline**: Developer ID in an ephemeral keychain, hardened runtime, `notarytool`, staple, DMG signed and notarized, Sparkle appcast generation, pre-release tag channel that does not touch Sparkle or Homebrew, Homebrew cask update, signature verification job. (PureMac, Mac Sai)
21. **Architecture**: keep nearly all logic in a SwiftPM package with tests that run without building the app (Peel, Mac Sai).

## 7. Pitfalls to avoid

1. **Substring name matching against `~/Documents`, `~/Desktop` or the home root.** Pearcleaner lists those roots and lost OpenSCAD user files (#587) and a "chro..." folder (#571). Never search user document folders for leftovers.
2. **Matching on Apple bundle-ID prefixes or short names.** Pearcleaner #618 (Pixelmator Pro, ID `com.apple.pixelmator`) swept up thousands of unrelated Apple items. Lemon's FinalShell bug (bundle ID `st`) matched every launch plist. Require whole-component matches and minimum lengths, and exclude `com.apple.*` data for non-Apple targets.
3. **Deleting a shared parent folder** (Firefox Nightly deleted the stable Firefox profile folder, #506). Rival and sibling checks must run before a folder is offered whole.
4. **Orphan detection by name substring against a skip list.** Pearcleaner's orphan scan lost browser, Autodesk, CrossOver and Adobe data and flagged Apple Shortcuts and CUPS folders (#477, #538, #617, #610). Use bundle-ID lineage and keep the automatic scope to cache-like folders.
5. **Cleaning other apps' caches and containers by default.** PureMac #144 broke Cursor, Figma, GitKraken, JetBrains Toolbox, Keka and Ableton; #142 disturbed iCloud Drive File Provider records. Treat `Containers`, `Group Containers`, `Caches/CloudKit`, `com.apple.bird`, `com.apple.cloudd`, and anything under an app's own signed bundle as off-limits, and never preselect another app's cache.
6. **Modifying signed app bundles** (architecture thinning, language-pack removal). Lemon #113 and PureMac #135/#136 produced broken or mixed-team-ID apps and system-wide failures; Pearcleaner #575 stripped `arm64e`. Do not edit third-party bundles.
7. **Permanent deletion paths and silent fallbacks.** Lemon's default is a root `remove`, and it falls back to permanent delete when Finder automation is denied while the UI says "Trash" (#149). Clean Me ran `rm -rf` as root (#48 reports 100+ GB of unintended loss; #37 deleted an unchecked Downloads folder). If a Trash move fails, stop and report; never fall back to `unlink`.
8. **A root service that trusts any caller.** Lemon's daemon accepts every XPC connection (#148). Pearcleaner's helper runs arbitrary `bash -c` as root and checks only the certificate chain. Use a code-signing requirement on the connecting process (team ID plus identifier), a fixed operation set, no shell, and a path allow-list inside the helper itself.
9. **Putting protected system items into the Trash.** Pearcleaner #616 moved a system-owned QuickLook container into its trash folder, after which Empty Trash failed permanently. Check SIP/System Policy flags and refuse restricted objects before moving.
10. **Path string comparison only.** Case-insensitive volumes, `/var` vs `/private/var`, symlinks, `/.vol/` and `/.nofollow/` spellings, Unicode normalization. Compare resolved paths and device+inode.
11. **Dev-tool tables that include user data** (`~/.vscode/extensions`, `Application Support/Cursor/User`, `~/.cargo`, `~/.pyenv`, `~/anaconda3`, `~/.m2`). Separate cache from data and mark data entries as manual.
12. **Triggering a TCC prompt storm or FDA confusion**: touching other apps' containers makes macOS ask "wants to access data from other apps". Probe with a small set of paths; do not enumerate inside other apps' containers.
13. **A trash-watching LaunchAgent that uses `WatchPaths`**; Lemon's froze Finder's desktop (#145). Use FSEvents in a lightweight agent, test with Dock Trash menus.
14. **Per-delete password prompts** (Pearcleaner #496, Lemon #108/#120). Register the helper once; batch privileged operations.
15. **Trusting stale app lists.** Lemon #154 showed the vendor's own uninstaller for the wrong app. Verify an uninstaller belongs to the selected bundle (team ID and path) before offering it.
16. **No release pipeline or provenance.** Pearcleaner's name was used by malware sites (#585 to #608). Publish signed, notarized builds from CI, document the official download and cask, and warn users about lookalike sites.
17. **Copying GPL, Commons Clause or proprietary code.** Lemon (GPL-3.0 / GPL-2.0), Peel (GPL-3.0), Latest (GPL-3.0) are copyleft. Pearcleaner is Apache-2.0 with Commons Clause, which forbids selling the software or derived products. System Data Unpacked is proprietary. PureMac's MIT label may not clear the derivation question noted in section 0. Use these only as reference for facts and ideas.
18. **Treating star counts as quality.** Several 2026 repos have very high stars for their age. Judge by the issue trackers and tests, not stars.
